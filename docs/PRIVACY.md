# Privacy and data handling

AI Usage is a local macOS menu-bar utility. The app and bundled extension have no telemetry or project-operated relay server. The services still receive their normal authenticated quota requests.

## Account connections

**Codex:** the app starts the installed `codex app-server`, initializes its control connection, and requests `account/rateLimits/read`. The installed client owns account authentication and its network request. AI Usage does not open Codex credential files or inspect conversations. It does not send a model prompt, and app-server analytics are disabled for this subprocess.

**Claude Code:** when available, the app requests usage over the installed client's control protocol. It does not send a user prompt. The probe disables tools, MCP configuration, hooks, remote-control startup, session persistence, automatic updates, and nonessential traffic through its launch options. Inherited API-key overrides are removed so this route uses the client's subscription sign-in. The client runs from a temporary empty directory, which the app removes afterwards. Unsupported clients display a connection error or can use the browser extension instead.

**Claude and Gemini browser usage:** the extension makes quota requests from a signed-in service tab. The browser attaches its existing session cookies to same-service requests; the extension does not extract cookie values or send them to AI Usage. It requests Claude organizations only to identify a single organization and refuses to guess when several exist. Gemini preserves a numeric account index selected in the tab. These identifiers stay in the browser.

The extension converts each response into an allowlisted quota object before contacting the Mac app. It forwards usage percentages, known window identifiers/durations, reset times, and observation time. It does not forward the full response, names, emails, account/organization identifiers, credentials, or conversation content. Its manifest requests storage, alarms, and access to `claude.ai`, `gemini.google.com`, and the fixed local listener. It does not request the browser cookies API or browsing-history permission.

## Local storage

The native app holds quota snapshots and errors in memory. It saves language, an optional Codex executable path, and the local pairing key in macOS `UserDefaults`. Launch-at-login is managed by macOS. It does not maintain quota history or raw-response logs.

The extension uses `chrome.storage.local` for the pairing key and per-provider status/timestamps. It does not use synchronized browser storage and does not persist quota snapshots or raw service responses. The popup clears the pairing-key input after saving and reports only whether it is configured.

The pairing key is generated by AI Usage and grants access only to its local quota receiver. It is stored in the user's preferences, not Keychain, so it is not intended to protect against software already running as that same macOS user. Clicking **Copy pairing key** places it on the system clipboard for pairing. It should not be included in public screenshots or issue reports.

The installed Codex and Claude clients and your browser maintain their own account/session state according to their respective settings. AI Usage does not delete or replace those sign-ins.

## Local transport and failures

The quota receiver binds only to IPv4 loopback `127.0.0.1:49627`. Local requests use HTTP with a random pairing key; they are not sent to an external host. Ordinary website origins are rejected, extension origins are narrowly validated, and both health and usage requests require the pairing key. Browser preflight requests are the sole authentication exception and do not accept usage data.

The receiver limits headers to 8 KiB, bodies to 64 KiB, and connection time to ten seconds. It requires explicit body length and JSON, rejects ambiguous HTTP framing, validates the provider schema, and invokes the app callback on its main actor. It does not return quota readings through its health endpoint.

Local client probes have bounded response time and are terminated after the request. Their stderr is discarded. UI and extension errors use fixed codes and messages, so raw server diagnostics are not displayed or logged. Missing values remain unknown, failed readings are marked stale, and a reset time passing does not fabricate a new full quota.

Use **Disconnect** in the extension to remove its pairing key, or **New pairing key** in the app to invalidate previously paired copies. Removing the extension stops browser collection. Quitting the app stops its listener and clears its in-memory readings.

## Reporting issues

Share a redacted screenshot, app version, provider, and the fixed error message. Never attach credentials, browser sessions, pairing keys, private account payloads, or conversation files. See [Security reporting](../SECURITY.md) for the reporting process.

AI Usage is not App-Sandboxed because it launches installed local clients. Only choose trusted executables. Builds are currently ad-hoc signed rather than Apple-notarized; release checksums verify file integrity but do not establish an Apple-verified publisher identity.
